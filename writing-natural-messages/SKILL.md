# Writing Natural Messages

## Core Principle

Write for the actual person, relationship, and channel. Make the message sound like something the sender wanted to tell this recipient now, not a polished summary written for an audience.

## Before Drafting

- Identify the main point, why it matters to the sender, and whether they want a response.
- Find the strongest personal truth: what helped, surprised, delighted, worried, or changed.
- Keep only details that clarify or support that point.
- For a repo, article, event, or earlier conversation, inspect the source when possible and use one exact detail. Never imply knowledge or experience without evidence.

## Drafting

1. Lead with the reason for sending. In recommendations, put the personal effect before the mechanics.
2. Follow one thread. Cut explanations that turn the message into an essay, product blurb, or README.
3. Match the recipient and channel. Use ordinary words; do not imitate dialect or manufacture intimacy.
4. Use short paragraphs for real shifts in thought. Add “oh, and” or “funny thing is” only when it fits the sender.
5. Never force filler, typos, fragments, or fake self-corrections. Natural writing is not damaged writing.
6. Make a real ask easy to answer. When only sharing, do not invent a call to action or response pressure.
7. Return the sendable message first as plain, copy-ready text. Do not wrap it in a Markdown blockquote (`>`), bullet list, label, or decorative container unless the user asks for that format. Explain only when asked.

## Quick Reference

| Message | Natural order |
|---|---|
| Recommendation | Personal effect → enough detail to trust it → link |
| Update | What changed → why it matters → action, if any |
| Sensitive topic | Concrete observation → honest feeling → invitation or permission |
| Reply | Answer their point → add useful context → stop |

## Example

Instead of opening with the implementation, lead with the result:

I tried this Codex fork and it’s great! It has smart auto-compaction based on tasks. When a task is finished, it compresses its context into a short memory instead of waiting until the context window is full. It feels a bit like context switching in an operating system. I almost never need to do manual compaction now.

## Common Mistakes

- Burying the important personal effect behind technical detail
- Restating every fact from the prompt
- Sounding like marketing, a review, or a formal email
- Adding generic praise, fake familiarity, or an unasked-for closing
- Making casualness performative with forced slang or imperfections
- Ending with “worth a look,” “thoughts?”, or another prompt the sender did not intend
